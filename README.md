# AI 代码导师 · 开源协作智能体

> 一套跑在本机的 FastAPI 服务，同时解决两件事：
> **教学生把代码写对**（检测 → 改错 → 注释 → 就地修改 → 归档管理），
> **帮贡献者把 PR 提明白**（克隆 → 解析 → 检索 → 生成测试 → 沙箱验证 → 自动修复 → PR 草稿）。

三个数字先放在前面：

| 指标 | 现状 |
| --- | --- |
| **测试** | 1112 个用例全部离线可跑（不依赖网络 / API Key / Docker），`ruff` 0 问题 |
| **验收脚本** | 12 个验收脚本 + 1 个前端行为测试脚本，共 **359 项**断言，全部实际跑过并附有输出（见第 8 节） |
| **真实模型验收** | 3 个示例作业 × 3 个功能全部通过，预设 bug 100% 命中（见第 8.3 节） |

**这台机器上没有大模型 Key、没有 Docker、甚至没有网络，项目依然能跑起来**——
缺什么就降级成什么，并且会在接口里如实标注（见 [2.4](#24-缺什么都能跑降级矩阵)）。

## 1. 项目功能

### 1.1 学生端：四个能力串成一条"写代码"的闭环

| 能力 | 一句话说明 | 需要大模型吗 |
| --- | --- | --- |
| **AI 自动检测** | 先本地查语法错误（精确到行列），再让 AI 查逻辑、边界与算法，给出评分 + 问题清单 + 学习建议 | 可选（没配则只出本地结论） |
| **AI 代码改错** | 分析错误 → 给出**修正后的完整代码** → 用四问讲透：错在哪 / 为什么错 / 怎么改 / 以后如何避免 | 可选（没配则只出本地分析） |
| **AI 注释生成** | 三层中文注释：文件级 + 函数级（功能/参数/返回值）+ 关键逻辑行内注释，按语言规范书写 | 可选 |
| **在线编辑** | 预览区直接改代码（行号 / Tab 缩进 / 回车自动缩进 / `Ctrl+S` 保存），改完能一键送回 AI 再检测 | 不需要 |

围绕这四件事还有一套"管理作业"的工具：

| 工具 | 说明 |
| --- | --- |
| **本地项目库** | 扫描你的代码文件夹并按语言分类。默认目录 `data/library/`，页面上**一直显示**它的完整路径，点「复制」即可粘到资源管理器打开 |
| **替换 / 删除** | 用本机另一个同类型文件覆盖某个作业；删除是移进 `.trash/` 回收站（可找回）。两个操作都要二次确认 |
| **文件自动分类** | 把散放的 `.c`/`.h`/`.java`/`.py` 归档到 `c/` `java/` `python/`，同名不覆盖、可重复执行 |
| **学习历史** | 每一次检测/注释/改错都落库，可回看当时的完整代码 |

> 想让学生只能看、不能改（例如项目库指向老师共享的公共目录）：
> 在 `.env` 里设 `LIBRARY__ALLOW_WRITE=false`，页面上编辑 / 替换 / 删除的入口会自动消失。

### 1.2 开源贡献端：从 Issue 到 PR 草稿的完整链路

| 步骤 | 能力 |
| --- | --- |
| 仓库解析 | GitPython 克隆 + Python AST / Tree-sitter 解析，提取文件、函数、类、圈复杂度 |
| 混合检索 | BM25 关键词召回 + FAISS 向量召回，RRF 融合重排（中文自然语言也能查代码） |
| 测试生成 | 调大模型生成 pytest 测试，落盘到沙箱工作副本 |
| 沙箱执行 | Docker 容器隔离执行（无 Docker 时降级为本地子进程，接口如实标注 `isolated: false`） |
| 自动修复 | 失败 → 归类根因（源码 bug / 测试 bug / 环境问题）→ 生成补丁 → 校验 → 应用 → 重跑，最多 N 轮 |
| PR 草稿 | 生成分支名、标题、改动清单与风险提示（未收敛时如实标注 `verified: false`） |

### 1.3 工程上的几个特点

- **两阶段 AI，不信模型的一面之词**：本地静态检查（AST / Tree-sitter）给出确定性结论，
  大模型只负责"说不清规则"的逻辑与算法，最后**本地再复核一遍**模型的产出。
- **全链路 Trace**：每个请求有 `trace_id`，日志、响应头、数据库记录能对上，便于排查"学生说点了没反应"。
- **降级而不报错**：没配 Key、没有 Docker、没网，接口照常返回，并明确告诉你缺什么、怎么补。
- **写操作四道锁**：项目库的编辑/替换/删除只能作用于配置目录内的已存在文件，
  保存带 `sha256` 乐观锁，删除默认进回收站，还能整体关成只读。
- **中文注释**：所有代码都带中文注释，说明函数用途、参数含义与关键逻辑，方便教学与二次开发。

## 2. 一键启动（推荐给不熟悉命令行的同学）

### 2.1 准备工作

只需要装 **Python 3.11 或 3.12**（[官网下载](https://www.python.org/downloads/)，安装时**勾选 "Add Python to PATH"**）。
`start.bat` 会自动创建虚拟环境并安装依赖，**不需要你手动 pip install**。

> 不建议用 Python 3.13+：部分依赖（faiss、tree-sitter 等）还没有对应版本的预编译包，安装可能失败。
> 脚本检测到大版本时会提醒你。

### 2.2 双击运行

```
双击  start.bat   →  检查 Python → 建虚拟环境 → 装依赖 → 启动服务 → 打开浏览器
双击  stop.bat    →  关闭服务（释放 8000 端口）
```

`start.bat` 做了这五件事：

| 步骤 | 做什么 | 为什么这么设计 |
| --- | --- | --- |
| 1/5 | 检测 Python 版本 | 优先用 `python`，其次 `py -3.11`/`py -3.12`；机器上装了多个 Python 时也能选对 |
| 2/5 | 创建/复用 `.venv` | 不污染系统 Python，卸载只需删文件夹 |
| 3/5 | 检查并安装依赖 | 用国内镜像（阿里云）加速，失败自动回退官方源；关键库缺一个就重装 |
| 4/5 | 检查 8000 端口 | 端口被占用时给出明确提示，而不是让服务静默启动失败 |
| 5/5 | 启动服务并打开浏览器 | **先等健康检查通过**再打开浏览器，避免看到一个"无法访问"的白页 |

启动成功后控制台会打印：

```
===========================================================================
   服务启动后会自动打开浏览器

   学生界面：http://127.0.0.1:8000
   接口文档：http://127.0.0.1:8000/docs
   健康检查：http://127.0.0.1:8000/api/v1/health

   关闭服务：在本窗口按 Ctrl+C，或双击运行 stop.bat
===========================================================================
```

### 2.3 手动启动（想在命令行里调试时）

```bash
python -m venv .venv
.venv\Scripts\activate                # Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
copy .env.example .env                # Linux/macOS: cp .env.example .env
python -m uvicorn app.main:app --reload
```

打开 **<http://127.0.0.1:8000>**（会自动跳到学生端页面）。
**不要双击 HTML 文件打开**——那样页面连不上后端。

> `.env` 是从模板复制来的，**只有一项需要你自己填**：`LLM__API_KEY`（见 [第 5 节](#5-ai-功能的原理)）。
> 不填也能用，检测/改错/注释会返回本地静态分析结果。

### 2.4 缺什么都能跑（降级矩阵）

| 能力 | 需要的条件 | 缺了会怎样 |
| --- | --- | --- |
| 页面浏览 / 项目库 / 文件分类 / 在线编辑 | 装好依赖即可 | — |
| AI 检测 / 改错 / 注释 / 导师三件套 | `.env` 里有 Key，**或**在网页「模型设置」里填自己的 Key | 返回 **200** + 本地分析结论，`ai_available=false`，`note` 里写明「请先在网页上输入 API Key」 |
| 生成测试 / 自动修复 | `.env` 里有 Key | 接口返回 503，提示"未配置 LLM__API_KEY" |
| 建索引 / 语义检索 | 首次需联网下载嵌入模型（约 180MB） | 自动降级为 `hashing` 嵌入（关键词匹配，精度低但可用） |
| 沙箱执行 | 有 Docker 最好 | 降级为本地子进程，**无隔离**，接口标注 `isolated: false` |

### 2.5 多模型与 API Key（想用自己的 Key 时看这里）

项目支持**多个模型**，并且允许使用者在网页上填**自己的** Key——
老师不必把自己的 Key 写进 `.env` 发给全班，学生也不用改配置文件。

#### 第一步：在 `.env` 里配置模型清单

```ini
# 一个模型一组配置，<ID> 用小写英文（deepseek / qwen / ollama …）
LLM__MODELS__DEEPSEEK__LABEL=DeepSeek 官方
LLM__MODELS__DEEPSEEK__PROVIDER=deepseek          # 写了它就自动补出 API 地址
LLM__MODELS__DEEPSEEK__MODEL_NAME=deepseek-chat
LLM__MODELS__DEEPSEEK__DESCRIPTION=去 platform.deepseek.com 申请 Key
LLM__MODELS__DEEPSEEK__API_KEY=                   # 留空 = 用网页上填的，或用全局兜底

LLM__MODELS__QWEN__PROVIDER=qwen                  # 通义千问（阿里云百炼兼容模式）
LLM__MODELS__QWEN__MODEL_NAME=qwen-plus

LLM__MODELS__OLLAMA__PROVIDER=ollama              # 本地模型：不需要 Key
LLM__MODELS__OLLAMA__MODEL_NAME=qwen2.5-coder:7b

LLM__DEFAULT_MODEL=deepseek                       # 默认选哪个（留空=第一个）
```

改完重启服务，页面右上角「模型设置」的下拉框里就会出现这三个模型。
**只有 `MODEL_NAME` 是必填的**，其余能推导就推导（`.env.example` 里带完整注释与更多例子）。

> **下拉框里只有一个模型？** 说明 `.env` 里**没有写上面这一段**，
> 页面显示的其实是"单模型写法"的兜底项——它的说明文字会点出来：
> `来自单模型配置（LLM__MODEL / LLM__BASE_URL / LLM__API_KEY）`。
> 这不是"项目只支持一个模型"：`LLM__MODEL` 填什么它就是什么；
> 想在下拉框里换着选，把 `LLM__MODELS__<ID>__*` 那几行加上、重启服务、再点模型卡片标题右边的 ↻ 即可。

#### 第二步：在网页上填 Key

1. 打开 <http://127.0.0.1:8000>，看左侧最上方的「**模型设置**」卡片；
2. 下拉框选一个模型（选项后面标着「需要填 Key / 后端已有 Key / 本地模型免 Key」）；
3. 在「我的 API Key」里粘贴你自己的 Key（默认打码显示，点「显示」可临时查看）；
4. 点「**保存并测试**」——
   它会先存 Key，**再真的调一次 AI 检测**来验证；成功时状态变绿显示
   「已连接 DeepSeek 官方（deepseek-flash）」，失败时变红并显示原因（如「Key 无效」）。

> 只保存不测试的话，Key 写错了要等学生点了「AI 检测」才发现——所以这一步是"存 + 试"。

#### 第三步：切换模型

直接在下拉框里换一个模型，再点一次「保存并测试」即可。
此后所有 AI 功能（检测 / 改错 / 注释 / 三个按钮）都会用**新选的模型**；
想换回后端配置的模型，点「清除 Key」。同一个会话里可以给多个模型各存一把 Key，
来回切换不用重填。

#### 安全注意事项（Key 不会被持久化）

| 事项 | 实际情况 |
| --- | --- |
| 存哪了 | **只存服务端进程的内存**（`app/core/api_key_manager.py`），**不写数据库、不写文件** |
| 什么时候消失 | 默认 **30 分钟无操作**自动清除（每次使用顺延）；服务重启也会清空 |
| 前端留了吗 | 没有。Key 只在提交那一刻发一次，之后前端只记一个会话号，**且只在 JS 变量里**（不写 localStorage / sessionStorage）→ **刷新页面需要重新填** |
| 日志里有吗 | 没有。日志只打会话号前 6 位 + 模型名 + 掩码 `sk-***`；错误信息也会脱敏（服务商回显 Key 时会被替换成 `***`） |
| 会回传给前端吗 | 不会。所有响应里都没有 `api_key` 字段，只回答 `has_key: true/false` |
| 想整体关掉 | `.env` 里设 `SECURITY__ALLOW_CLIENT_KEY=false`，网页填 Key 的接口会返回 403 |

## 3. 如何使用 HTML 界面

服务启动后浏览器打开 **<http://127.0.0.1:8000>**，只有一个页面（学生端）。

### 3.1 界面总览

```
┌──────────────┬────────────────────────────┬──────────────────────┐
│ ① 选择你的代码│                            │                      │
│ ② 本地项目库  │   代码预览 / 在线编辑器     │   ⑤ 分析结果         │
│ ③ 自动分类    │   [编辑✎][保存][取消][清空] │   · 评分 + 等级      │
│ ④ 历史记录    │  [AI 检测][生成注释][改错]  │   · 问题清单         │
└──────────────┴────────────────────────────┴──────────────────────┘
```

三栏都可以拖动分隔条调整宽高，尺寸记在浏览器里，下次打开还是你习惯的样子。

### 3.2 典型用法

1. **放代码**：把作业文件拖进「① 选择你的代码」的虚线框，或点它选择文件；
   也可以展开「没有文件？直接粘贴代码」贴一段，或在中间区域直接 `Ctrl+V`。
2. **看分类**：右侧会显示识别出的语言（C / Java / Python）与函数/类清单。
3. **跑 AI**：依次点三个按钮
   - **AI 检测** → 0-100 评分、等级、问题清单（含行号与修改建议）、做得好的地方；
   - **生成注释** → 带中文注释的完整代码；
   - **自动改错** → 修正后的完整代码 + 逐条「改前 / 改后 / 为什么」。
4. **换文件**：「② 本地项目库」列出本机代码文件（按语言分类，可筛选），点一下即可载入。
5. **改代码**：点标题栏的「**编辑 ✎**」就地修改，`Ctrl+S` 保存（详见 [4.4](#44-入库之后接着改在线编辑--替换--删除)）。
6. **回看**：「④ 历史记录」保存了每一次操作，点条目能重新载入当时的代码。

> **边写边查**：编辑模式下三个 AI 按钮照常可用，而且分析的是"你正在写的这一版"
> （不必先保存），适合"改一行 → 点检测 → 看评分有没有变好"这种循环。

### 3.3 三个拖拽区语义不同（界面上也写清了）

| 拖到这里 | 会发生什么 | 用途 |
| --- | --- | --- |
| **① 选择你的代码**（左上虚线框） | 载入预览区 + 识别语言与结构，**不入库** | 「打开看看这段代码有什么问题」 |
| **② 本地项目库**（虚线框） | **入库**：保存到服务器 → 按语言归档 → 刷新列表 | 「这是我的作业，交上去」 |
| **③ 代码预览区**（中间） | 载入预览区 + 语法高亮，**不入库** | 在中间看代码时顺手拖进来 |

**为什么预览区不入库**：入库会真的在服务器上创建文件、还会按语言搬进 `c/` `java/` `python/`。
如果预览也算入库，学生只想看一眼别人的代码，项目库就多出一份，列表很快就乱了。

### 3.4 界面细节

| 想做什么 | 怎么操作 |
| --- | --- |
| 代码区更宽一点 | 拖动三栏之间的**竖分隔条**（鼠标变成 `col-resize`） |
| 代码区更高一点 | 拖动代码区与按钮之间的**横分隔条**（鼠标变成 `row-resize`） |
| 恢复默认尺寸 | **双击**任意分隔条 |
| 微调 / 不用鼠标 | 点中分隔条后按 **← →** 或 **↑ ↓**（按住 Shift 一次 60px） |

最小宽度已经限制好（左侧 200px / 中间代码区 400px / 右侧 280px），怎么拖都不会把某一栏拖没；
窗口变窄到放不下三栏时，分隔条会自动收起。

### 3.5 大文件不会卡

超过 **500 行**时先高亮前 500 行，其余内容**立刻以纯文本显示完整**
（能滚动、能复制，不是留白等加载），再由 `requestIdleCallback` 在浏览器空闲时逐块补上颜色。
底部会提示「文件较大（N 行），已先显示全部内容，语法高亮将分批完成」。

## 4. 如何添加学生代码

### 方式一：直接拖进学生端（最简单）

把文件拖到「② 本地项目库」的虚线框，后端会依次做三件事：

```bash
# 1) 把文件存到项目库（同名同内容重复时返回 409「文件已存在」）
curl -X POST http://127.0.0.1:8000/api/v1/files/upload -F "file=@我的作业.py"

# 2) 按语言归档（.py → python/、.c/.h → c/、.java → java/）并写入 SQLite 台账
curl -X POST http://127.0.0.1:8000/api/v1/files/scan -H "Content-Type: application/json" -d '{}'

# 3) 查看台账（文件名 / 语言 / 路径 / 大小 / 入库时间）
curl http://127.0.0.1:8000/api/v1/files/list
```

拖入之后的三种情况都会明确告知：

- 重复拖入**同一个文件**（同名且内容相同）→ 提示「文件已存在」，不重复添加；
- 同名但内容不同（两个学生都叫 `main.c`）→ 自动另存为 `main_1.c`，**绝不覆盖**；
- 拖入 `.txt` / `.zip` 这类非源码文件 → 明确告知"只支持 .c/.h/.java/.py"。

### 方式二：放进 `data/library/` 并一键归档（适合整理一学期的作业）

1. 把散放的作业复制到项目根目录的 `data/library/`（`start.bat` 第一次运行时会自动创建，
   里面已经摆好了 `c/` `java/` `python/` 三个空目录）；
2. 学生端「② 本地项目库」点右上角 ↻ 刷新即可看到；
3. 想把它们**按语言归位**，跑一次归档（建议先预演）：

```powershell
# 预演：只告诉你"打算把谁移到哪"，不动文件、不写库
Invoke-RestMethod "http://127.0.0.1:8000/api/v1/files/scan" -Method Post `
  -ContentType "application/json" -Body '{"dry_run": true}'

# 正式归档
Invoke-RestMethod "http://127.0.0.1:8000/api/v1/files/scan" -Method Post `
  -ContentType "application/json" -Body '{}'
```

结果：`.c` / `.h` → `data/library/c/`，`.java` → `data/library/java/`，`.py` → `data/library/python/`。

三条"不会把作业弄丢"的保证：

1. **绝不覆盖同名文件** —— 重名自动加 `_1` `_2` 后缀，接口 `note` 里写明"已被重命名"；
2. **可以反复点** —— 归档目录与回收站在扫描时会被跳过，不会出现 `c/c/main.c` 这种套娃；
3. **未知文件默认不动** —— `.txt`/`.md`/`.go` 只登记、不移动（可能不是作业）。
   要一起归档就把请求体写成 `{"move_unknown": true}`。

### 方式三：让学生扫自己电脑上的作业文件夹

编辑 `.env`，改这两项（多个目录用逗号分隔），重启服务生效：

```ini
# 左侧「② 本地项目库」列表从哪里扫描；编辑保存 / 替换 / 删除也作用在这些目录里
LIBRARY__ROOTS=D:\我的作业, E:\课程代码

# 文件自动分类与拖拽入库把文件放到哪（会真的写入磁盘）
CLASSIFIER__ROOT=D:\我的作业
```

> **安全边界**：能被扫描的目录**只能在后端配置**，页面上没有任何入口能指定任意路径。
> 读和写都会校验目标确实落在根目录内，`../../` 这类路径穿越与指向外部的软链接都会被拒绝。

### 4.4 入库之后接着改：在线编辑 / 替换 / 删除

学生交完作业最常做的事就是"再改两下"，这三种操作都在页面上完成：

| 操作 | 入口 | 效果 | 安全设计 |
| --- | --- | --- | --- |
| **在线编辑** | 代码区标题栏「编辑 ✎」 | 就地改代码，`Ctrl+S` 保存写回磁盘 | 打开时记下 `sha256`，保存时带回去比对；文件若被别处改过 → **409 拒绝覆盖** |
| **替换** | 列表项悬停 → 「替换」 | 用本机另一个文件的内容覆盖这个路径 | 必须**同扩展名**；替换前二次确认 |
| **删除** | 列表项悬停 → 「删除」 | 移进项目库文件夹下的 `.trash/` | 带时间戳、可手动找回；页面上**没有**"一键永久删除" |

几个如实说明的点：

- **不是所有代码都能保存**：只有"项目库里的文件"才写磁盘。拖进 ①/③ 只看一眼的代码、
  粘贴进来的代码，点保存只会更新预览，并明确提示"没有写进任何文件"。
- **保存会统一成 UTF-8**：原文件是 GBK（Windows 记事本常见）时中文不会乱，但编码会变，提示里会说明。
- **换行符保留原样**：原来是 CRLF 的文件保存后还是 CRLF，不会因为改一行就整份变样。
- **写入是原子的**：先写同目录的临时文件再替换，中途失败也不会留下半截作业。
- **可以整体关掉**：`LIBRARY__ALLOW_WRITE=false` 时这三个入口直接从界面消失。

对应的后端接口（前端就是这么调的）：

```bash
# 读取（返回里带 sha256，前端拿它做乐观锁基准）
curl "http://127.0.0.1:8000/api/v1/library/file?path=python/homework1.py"

# 在线编辑保存 / 用本机文件替换（同一个接口）
curl -X PUT http://127.0.0.1:8000/api/v1/library/file \
  -H "Content-Type: application/json" \
  -d '{"path":"python/homework1.py","code":"def add(a, b):\n    return a + b\n"}'

# 删除（默认进回收站；加 permanent=true 才是彻底删除）
curl -X DELETE "http://127.0.0.1:8000/api/v1/library/file?path=python/homework1.py"
```

## 5. AI 功能的原理

三个功能都遵循同一套**「本地先查，AI 再判，最后本地复核」**的两阶段设计。
理由很实际：本地解析器（AST / Tree-sitter）给出的结论是确定性的，比让模型"目测第几行出错"准得多，
也更省钱；而逻辑、算法、边界条件这些"说不清规则"的问题才交给大模型。

### 5.1 AI 自动检测（`app/services/code_checker.py`）

```
代码 + 语言
  ├─ 阶段 1 本地静态检查（毫秒级、不花钱、不联网）
  │    语法：Python 用内置 ast，C/Java 用 tree-sitter 的 ERROR/MISSING 节点
  │          → 精确到「第几行第几列」
  │    结构：函数/类清单、圈复杂度、最长函数
  │    风格：缩进混用、行尾空格、超长行、注释比例、命名规范
  │    风险：Python 可变默认参数 / 裸 except / == None
  │          C 的 gets/strcpy/sprintf/scanf("%s")，Java 的 == 比字符串 / 空 catch
  └─ 阶段 2 AI 深度检测
       把阶段 1 的结论一起塞进 Prompt，要求「不要重复报告」，
       让它专注逻辑、边界与算法，输出：
         错误 / 风格建议 / 潜在风险 / 学习建议 + 0-100 评分
```

**Prompt 设计要点**：① 写明"读者是大一新生"，输出会从"代码评审腔"变成"讲题腔"；
② 注入本地结论并要求别重复，把 token 花在真正需要判断的地方；
③ 给评分锚点（90+ 可以直接交作业 / 40-59 跑不起来），避免模型一律给 80 分；
④ 禁止编造行号，且代码层再兜一道——越界行号一律置空。

**评分规则（完全可解释）**：AI 给分的基础上，**有语法错误时硬性压到 45 分以内**——
代码都跑不起来，不该因为模型心情好就给高分。没配模型时用本地规则打分
（100 分起扣，并封顶 85 分——本地规则看不出逻辑对错，不给"优秀"档）。

### 5.2 AI 代码改错（`app/services/code_fixer.py`）

```
① 本地分析   ast / tree-sitter 定位语法错误（精确到行列）+ 风格与常见坑
② AI 修正    每条修改必须回答四问：
             what 原来错在哪里 → why 为什么错 → how 怎么改 → avoid 以后如何避免
③ 本地复检   把 AI 给的代码**再跑一遍语法检查**：
             · 改前有语法错误、改后没有了  → verified=true
             · 改后仍有语法错误           → verified=false（明确告知仍需人工确认）
             · 改前就没有语法错误（逻辑错）→ verified=true，但注明
               "逻辑正确性本地无法验证，请自己跑一组测试"
```

**第 ③ 步是这个功能的关键**："AI 说改好了"和"真的能跑"是两件事。
`verified` 只代表语法层面，接口会在 `verification.note` 里写清这条边界，
避免学生把 `verified=true` 理解成"逻辑也对、可以直接交作业"。

**四问结构的价值**：只给"改前/改后"而不讲"为什么"和"以后怎么避免"，学生下次还会犯同样的错。
第 ④ 问是"改错"和"学会"的分界线，多数自动修复工具都不给。

### 5.3 AI 注释生成（`app/services/comment_generator.py`）

```
① 本地分析   解析出函数清单与签名（告诉模型该给谁写注释、参数有哪些）
② AI 生成    文件级 + 函数级 + 关键行内，三层注释按语言规范书写
③ 本地复检   ① 语法有没有被注释写坏
             ② **代码逻辑有没有被改动**（本功能最关键的一条）
             ③ 每个函数是否都拿到了注释（覆盖率）
             ④ 有没有文件级注释
```

| 层级 | 内容 | Python | Java | C |
| --- | --- | --- | --- | --- |
| 文件级 | 这个文件做什么 | 模块 docstring | 文件头 `/** */` | 文件头 `/* */` |
| 函数级 | 功能 + 参数 + 返回值 | docstring（`Args:`/`Returns:`） | Javadoc（`@param`/`@return`） | 函数上方 `/* */` |
| 行内 | 只解释难懂的关键逻辑 | `#` | `//` | `//`、`/* */` |

**为什么必须复核"代码有没有被改动"**：注释类任务最危险的不是"注释写得不好"，
而是模型顺手把学生的代码改了（实测它很爱把 `for i in range(len(a))` 改成 `for x in a`）。
本功能用 AST / 去注释后逐字符比对来客观判断，而不是让模型自己说"我没改"。

### 5.4 防幻觉的四个手段

| 手段 | 用在哪 | 效果 |
| --- | --- | --- |
| 本地结论注入 Prompt | 检测 / 改错 | 模型不重复已知问题，专注逻辑层 |
| 行号越界即置空 | 检测 | 模型编造的"第 999 行"不会出现在界面上 |
| 语法复检 | 改错 | 模型给的代码若仍有语法错误，`verified=false` |
| 代码未改动复核 | 注释 | 只加注释、不改逻辑，`code_unchanged` 客观可查 |

### 6.5 模型清单与 API Key 会话（`/api/v1/models`、`/api/v1/auth`）

这两个模块让**学生在网页上选模型、填自己的 API Key**（Key 只存内存，不落库、不进日志）：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/models/list` | 可用模型清单：ID、展示名、提供商、是否需要 Key、后端是否已有 Key（**不含 Key**） |
| POST | `/api/v1/auth/set_key` | 把网页上填的 Key 存进内存会话；返回 `session_id`，前端放 `X-Session-Id` 头带回来 |
| POST | `/api/v1/auth/clear_key` | 清除 Key：不带 `model_id` 清整个会话（退出），带上就只清那一个模型 |
| GET | `/api/v1/auth/status` | 查会话状态：存了哪些模型、什么时候过期（**只回"有没有 Key"**） |

安全约定（改这几个接口时务必守住）：

- **只走请求体**：Key 绝不放在 URL 查询串里（查询串会被访问日志原样打印）；
- **只进不出**：响应里没有 `api_key` 字段，只回答 `has_key`；内部日志也只打掩码 `sk-***`；
- **会过期**：默认 30 分钟无操作自动清除，每次使用顺延（`SECURITY__API_KEY_TTL_SECONDS`）；
- **有上限**：内存里最多留 `SECURITY__MAX_SESSIONS` 个会话，超出淘汰最久未使用的；
- **可关闭**：`SECURITY__ALLOW_CLIENT_KEY=false` 时 `set_key` 直接返回 403，只能用 `.env` 里配好的 Key。

## 9. 常见问题

**Q：启动后 AI 按钮是灰的 / 提示"AI 未启用"？**
没配 `LLM__API_KEY`。这是刻意设计：返回 503 并说明原因，而不是拿假 Key 去 401。
照 [第 5 节](#5-ai-功能的原理) 填好 `.env` 后重启即可。**没配也能用**——本地项目库、文件分类、
在线编辑，以及检测/改错/注释的本地分析部分都照常工作。

**Q：双击 `start.bat` 窗口一闪就没了？**
一般是 Python 没装或没加入 PATH。先装 Python 3.11/3.12 并勾选 "Add Python to PATH"。
脚本对中文与编码做了处理（`chcp 936` + GBK + CRLF），不会出现乱码导致的解析错误。

**Q：端口 8000 被占用？**
双击 `stop.bat` 释放，或改 `.env` 里的 `APP__PORT`（同时改 `start.bat` 顶部的 `APP_PORT`）。

**Q：第一次启动很慢？**
首次要下载依赖（几分钟）。构建检索索引时还会下载嵌入模型（约 180MB）；
想跳过就把 `RETRIEVAL__EMBEDDER=hashing`（零下载，精度低一些）。

**Q：删掉的文件去哪了？**
在项目库文件夹下的 `.trash/`，名字形如 `20260218-153000__python__homework1.py`。
把名字改回 `homework1.py` 再移出 `.trash` 就恢复了。不想要回收站就把
`LIBRARY__TRASH_DIR_NAME` 设成空字符串（删除即彻底删除）。

**Q：保存时提示"文件在别处被改动过"（409）？**
你打开这个文件之后，它在别处（记事本、另一个编辑器、Git 切换分支）被改过。
页面记的是打开那一刻的内容指纹，为了不覆盖新内容会拒绝保存——
重新打开一次文件再改即可。

**Q：`/sandbox/status` 显示 `isolated: false`？**
没有可用的 Docker daemon，沙箱降级成了本地子进程——**没有隔离能力**，
被测代码会以你的用户身份直接跑在宿主机上。只建议用来执行自己生成的代码。

**Q：Windows 上 `curl` 发的 JSON 报 `JSON decode error`？**
PowerShell 5.1 向原生命令传参时会吃掉 JSON 里的内层双引号。请用 `Invoke-RestMethod`
（见 `使用教程.md` 的场景 A），或改用 `curl.exe --data-raw` 并把 JSON 写进文件。

**Q：怎么彻底清理数据？**
删掉 `data/` 下的 `app.db`、`index/`、`repos/`、`workspaces/` 即可
（`data/models/` 是模型缓存，删了下次要重新下载）。**学生作业在 `data/library/`，别误删。**

**Q：我在网页上填了 Key，为什么刷新页面就要重填？**
这是刻意的：Key 与它对应的会话号都只放在内存里（后端进程内存 + 前端 JS 变量），
不写数据库也不写浏览器存储，刷新即失效。想少填几次可以把 Key 写进 `.env`
（`LLM__API_KEY` 或某个模型的 `API_KEY`），那样就是"后端自带的 Key"。

**Q：点了「保存并测试」显示"连接失败：API Key 无效或已过期"？**
说明这把 Key 在服务商那边不通过（可能复制少了字符、已过期、或该账号没开通这个模型）。
重新粘贴一次即可；如果确认 Key 没问题，检查下拉框选的模型与 Key 是不是同一家的
（DeepSeek 的 Key 拿去调通义会 401）。

## 10. 能力边界（如实说明）

以下几点是当前实现的真实限制，不是配置问题：

1. **容器隔离未在无 Docker 的环境验证**。代码里 Docker 路径的容器参数有 13 项单元断言覆盖
   （不挂 docker.sock、`cap_drop ALL`、只读根文件系统等），但"容器真能跑起来"需要在有 Docker 的机器上复验。
   开发机没有 Docker daemon，沙箱实际走的是 local 后端。
2. **AI 效果依赖所用模型**。已用真实模型做过验收（3 个示例作业 × 3 个功能，10/10 通过），
   但那只覆盖少量示例文件，**不代表任意学生代码都可靠**；正式教学前建议抽样复验。
3. **跨语言检索是短板**。默认嵌入模型在"中文查询→中文文档"上表现好，
   "中文查询→纯英文代码"命中率约 40%，查询里带上英文标识符会明显改善。
4. **克隆 / 索引 / 生成 / 执行都在请求内同步完成**，大仓库或慢模型下请求会比较久；
   架构上应该改成"返回 202 + task_id，后台执行"。

更细的操作步骤、逐条命令与实测输出见 [`使用教程.md`](使用教程.md)。
